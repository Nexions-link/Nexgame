# Рабочие указания для ассистента-разработчика NexGameWorld

Основной рабочий код — сферическая NexGameWorld в `planet-test/`; плоский прототип архивирован. Перед работой проверяй фактический текущий `main`, историю релизов и `planet-test/version.json`. Главный публичный вход — `https://nexions.ru/nexgameworld/`; публикация зеркалируется в `Nexions-link/Nexions-portal` и требует проверки реального сайта.

## Обязательный релизный шлюз — все чаты NexGameWorld

Это правило проекта действует **при любой работе с игрой, в любом чате, независимо от того, над какой функцией ведётся работа**. Просьба пользователя сообщать о готовности **не отменяет** проверок.

1. **До публикации:** установить актуальный `Nexions-link/Nexgame/main`, проверить синтаксис и тесты; отдельно сверить `server/index.js` (BUILD), `planet-test/version.json` (version) и `planet-test/index.html` (data-build). Все три значения должны совпадать согласно `server/tests/release-consistency.test.mjs`. При клиентском изменении также обновлять серверный BUILD и дождаться фактического деплоя VPS (https://api.nexions.ru) — либо прежде согласованно изменить весь контракт версионирования и все проверки.
2. **Автоматическая доставка:** проверить успешное выполнение GitHub Actions `NexGameWorld Spherical and Server CI`, `NexGameWorld server checks` и `Sync NexGameWorld to nexions.ru`. **Не считать ручное копирование файлов в Nexions-portal полноценным релизом**: оно обходит тесты и не гарантирует выкладку GitHub Pages. Сбой, отмена или пропуск workflow — это не успех.
3. **Публикация:** проверить совпадение файлов `Nexgame/main` и `Nexions-portal/nexgameworld/`, файл `upstream-commit.txt`, а также успешный **последний** `pages build and deployment` на коммите портала, включающем обновление.
4. **Живой адрес:** выполнить `ops/audit-production.mjs` через сетевую среду GitHub Actions и подтвердить **зелёную проверку `Verify live NexGameWorld on nexions.ru`**, полученную **после последней публикации**. Проверять непосредственно `https://nexions.ru/nexgameworld/planet-test/version.json`, `index.html`, нужные JS/CSS/GLB, `/nexgameworld/` и VPS (https://api.nexions.ru) `/health`, `/ready`. Для ответа «опубликовано и доступно» необходимо наличие подтверждения с внешней сети. GitHub-репозиторий, raw.githubusercontent.com, локальная симуляция и успешный Pages workflow не заменяют эту проверку.
5. **Отчёт:** различать «код внесён в основной репозиторий», «файлы зеркала синхронизированы», «Pages опубликовал» и «сайт Nexions.ru реально проверен, можно тестировать». Если хоть один шлюз не пройден, **не писать «готово», «опубликовано» или «можно тестировать» как свершившийся факт**; сообщать точный статус, версию и что именно не подтверждено. Не отправлять ссылку как подтверждение доступности.
6. На смене чата сначала читать этот файл и последнюю историю GitHub Actions. Не полагаться на статус из прежнего диалога, память о версии, статус отдельных тестов или написанное в `version.json`.

**Причина правила:** 26.10.2026 GitHub-зеркало содержало 0.6.45.21, но публичный сайт ещё отдавал 0.6.45.20; GitHub Actions исходного CI и production audit были красными. Сообщать «готово» до проверки публичного сайта запрещено.

## Новое генеральное ТЗ: графический ремастер R1 (30.10.2026)

**Источник требований для полного графического переосмысления:** [docs/NGW_VISUAL_REMASTER_SPEC.md](docs/NGW_VISUAL_REMASTER_SPEC.md). **Журнал выполнения по номерам G-01…G-41:** [docs/NGW_VISUAL_REMASTER_PROGRESS.md](docs/NGW_VISUAL_REMASTER_PROGRESS.md).

Если пользователь говорит «Выполняем G-XX», сначала прочти это ТЗ и журнал, проверь свежие основной код и версию, выполни именно указанный пункт как отдельную законченную задачу с тестированием, сравнением реальной игровой сцены с эталонным изображением, проверкой коллизий/онлайна и честным отчётом о статусе публикации. После каждого такого этапа обновляй журнал и проходи обязательный релизный шлюз. Одна только документация или концепт не являются выполнением игрового этапа.

**Важное уточнение владельца (30.10.2026): штатную игровую камеру НЕ перерабатывать.** Текущее расположение, высота, наклон, дальность, FOV, следование, свайпы и масштаб его устраивают. Любой графический ремастер реализовывать изменением ассетов и визуала сцены, а не изменением существующего игрового ракурса. G-32 теперь — проверка совместимости графики со штатной камерой; G-01 — отдельные добровольно включаемые контрольные ракурсы только для визуальной диагностики. Не менять настройки штатной камеры без нового прямого запроса пользователя.

Эталон R1 — предоставленная пользователем 30.10.2026 вертикальная иллюстрация живописной игровой сцены с объёмным лесом, детальной тёплой тропой, богатым подлеском, многослойными кронами и мягким солнечным светом. Художественное совпадение проверять по реальным кадрам рендера, а не генерацией новой картинки. Существующие тяжёлые экспериментальные деревья не возвращать автоматически в массовую сцену: прежние просадки FPS требуют подтверждённого LOD/инстансинга или отдельного согласованного решения.

## Библиотека деревьев Шепчущего леса

**Единственный полный источник требований:** [docs/NGW_TREE_LIBRARY_SPEC.md](docs/NGW_TREE_LIBRARY_SPEC.md). **Фактический прогресс:** [docs/NGW_TREE_LIBRARY_PROGRESS.md](docs/NGW_TREE_LIBRARY_PROGRESS.md).

По новой команде пользователя о деревьях/материалах:
1. Прочти оба файла, проверь текущий репозиторий, свежие коммиты и последнюю версию.
2. Выполняй первый незавершённый этап Т0–Т4 автономно и последовательно, без избыточных согласований.
3. Художественное качество — максимальное, первоначально без ограничений под iPhone и целевого FPS. Оптимизация — отдельная задача; сломанные сборки недопустимы.
4. Сначала визуальные тесты в Саду Каменного ветра, потом ограниченная интеграция в Шепчущий лес. Сохраняй сферическую геометрию, коллизии, квесты, NPC, серверные правила и мультиплеер.
5. Не используй чужие текстуры и модели без разрешения/лицензии; делай оригинальные ассеты.
6. Тестируй каждый этап и фактическую публикацию на основном адресе. Фиксируй коммит, версию, ссылку и тесты в файле прогресса и отчёте.
7. Изменения пользовательских данных, платные сервисы, новые секреты, разрушительные операции и серверные контракты требуют отдельного решения пользователя.

**Разделение ответственности:** пользователь тестирует сборки и даёт замечания; ассистент выбирает и реализует технические решения при получении задания. Фоновая разработка вне активного запроса не предполагается.

## Рабочая эксплуатация после переноса на VPS (31.10.2026)

- Канонический игровой API: `https://api.nexions.ru/api/ngw`; авторизованный мир: `wss://api.nexions.ru/ws/nexgameworld/auth`. Проверять клиент, страницу аккаунта и CSP; прежний Render-адрес не является production.
- Доставка: `.github/workflows/deploy.yml`, VPS `94.103.87.93`, пользователь `ngw-deploy`, только `nexgameworld.service`. Полный релиз расположен в `/opt/nexgameworld/releases/deploy-RUNID-ATTEMPT/`; `current` указывает на его `server/`. Не раскладывать модули поверх общих каталогов старых релизов.
- Приватная конфигурация сохраняется в `/opt/nexgameworld/shared/server.env`; не выводить её и не заменять целиком при обычном релизе. Сервер слушает `127.0.0.1:9800`.
- До активации: серверные тесты, полная упаковка исходников, фактический импорт spherical-world и SELECT 1. После: локальные и публичные /health, /ready, совпадение BUILD, готовность аккаунтов/экономики, отсутствие ошибок сохранения и TLS WebSocket upgrade. При неудаче workflow возвращает предыдущую ссылку current и перезапускает только игровой сервис.
- TeamSpeak, Docker и Nginx не изменять. Не удалять прежние релизы и данные игроков в рамках доставки игры.
