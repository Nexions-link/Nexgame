# Аудит экипировки и боя охотника — 13.11.2026

Проверен активный сферический клиент `planet-test/` и сервер `Nexions-link/Nexgame`, исходный `main`: `cf5c79c11630bb94a613066f37a0818b5886b302` (0.6.46.3). Изолированный NexGameWorld-Remaster не является действующей игрой и не изменён.

Кандидат исправлений: **0.6.46.4**. Этот документ фиксирует изменения кода, а не подтверждение публикации на nexions.ru.

## Найдено и исправлено

| Проблема | Причина и исправление |
| --- | --- |
| Лук и щит отображались в левой руке; щит также давал броню и блок | Лук не был помечен двуручным, правила проверяли только слот и уровень. `twoHanded`, `equipmentConflict` и `effectiveShield` теперь используются общими характеристиками, серверной экипировкой и визуалами. Новые конфликтующие комбинации отклоняются без изменения инвентаря. |
| Старые сохранения уже могли содержать лук и щит | Предмет остаётся в сохранении и доступен для снятия. С двуручным луком он не даёт характеристик и блока, не попадает в активную сетевую экипировку и не отображается. Окно персонажа объясняет неактивность. Миграция/удаление вещей не выполняется. |
| Охотник сохранял позу лучника после смены оружия; удалённые выстрелы не анимировались | Поза зависела от класса, а сетевой обработчик распознавал только умения воина. Теперь поза и видимость зависят от фактического оружия; обрабатываются все пять выстрелов. Лук повторно используется, устаревшие запросы загрузки щита отменяются. |
| Попадание противника прибавляло охотнику 5 маны | Клиент безусловно применял правило ярости воина. Прибавка теперь ограничена воином; мана остаётся серверной. |
| Автовыстрел нельзя было выключить на ходу или после снятия лука | Проверки неподвижности и оружия выполнялись перед выключением режима. Отключение теперь предшествует проверкам включения. |
| Манекен игнорировал бонусы выстрелов и показывал неверный урон | Использовалась формула ближнего боя. Клиент и сервер теперь вызывают одну `rollHunterDamage`; серверный баланс не изменён. |
| Орк-охотник подписывался тауреном-воином и получал подсказку о Рывке | Подписи были жёстко заданы. Раса, класс, следующее и открывшееся умение берутся из профиля и реестра способностей (Залп на 4-м, Прицельный выстрел на 8-м). |

Обычные сочетания одноручного оружия со щитом, атомарный обмен предмета с заполненным рюкзаком и ограничения смены брони в бою сохранены. Новые серверные контракты, камера, геометрия мира, учётные записи и содержимое БД не изменялись. Версии BUILD, HTML и manifest согласованы; обновлены версии зависимых клиентских импортов и входа в создание героя.

## Проверки

- `npm run check` и `npm test`: активный клиент, графические и игровые регрессии.
- `npm run check --prefix server`, `npm test --prefix server`: мультиплеер, боевые правила, группы, экипировка, интеграция и согласованность версии.
- Серверные `test:accounts`, `test:progress`, `test:economy`, `test:world-auth`.
- `node --test ops/audit-production.test.mjs tests/skills.test.mjs`: логика внешнего аудита без live-запросов и общие способности.
- Новые проверки: оба порядка экипировки лук/щит, отсутствие мутаций при отказе, сохранность и снятие старого щита, отключение всех его бонусов, смена оружия и отмена запоздалых загрузок, сетевые анимации всех выстрелов, мана при получении урона, выключение автовыстрела на ходу, урон манекена и классовые сообщения повышения уровня.

Локальные PostgreSQL-тесты без `NGW_PROGRESS_TEST_DATABASE` пропускают интеграционные сценарии с БД; их отдельные jobs должны пройти в GitHub Actions до слияния. Браузерная проверка Chromium не заменяет реальный iPhone Safari и проверку авторизованного боя нескольких людей на рабочем сервере.
