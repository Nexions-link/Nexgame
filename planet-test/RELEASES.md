## Правило для всех будущих изменений в `planet-test/`

**Каждое видимое изменение должно сопровождаться новой версией.**

1. Исправление ошибки или небольшое улучшение: увеличить третий номер (`0.1.0 → 0.1.1`). Новая крупная игровая функция: увеличить второй номер и обнулить третий (`0.1.x → 0.2.0`).
2. Добавить запись об изменении в этот файл и обновить `version.json`: `version`, `title`, `publishedDate`, `changes`, `history`.
3. В `index.html` обновить `data-build`, видимую надпись `PT ...`, текст загрузки внутри панели версии и `<title>`.
4. Обновить параметр `?v=` у главного файла `planet.js` и у изменённых JS-модулей, чтобы iPhone Safari действительно загрузил новый код.
5. **Публиковать `index.html` последним**, а `version.json` до него. Тогда новый интерфейс не будет ссылаться на несуществующие файлы. Проверить синтаксис JS и затем статус GitHub Pages `success`.
6. URL самой страницы всегда оставлять **без параметров версий**. Параметры допускаются только у загружаемых ресурсов и при внутренней проверке обновлений.
7. Не изменять `app.html`, `game.js`, `style.css` и сервер Render ради исправлений в тестовом сферическом мире.

## Как узнать, что Safari показывает старую сборку

Кнопка `PT …` показывает номер из HTML **текущей вкладки**, а сообщение «На сайте» берётся из нового запроса к `version.json` на GitHub Pages. Если номера различаются, вкладка ещё использует старый HTML/JS. Нажать «Обновить игру». Если версия всё равно старая — закрыть вкладку и вновь открыть постоянную ссылку.

Когда новая запись уже в GitHub, но GitHub Pages ещё не закончил публикацию, индикатор может продолжать показывать предыдущий опубликованный выпуск. Это ожидаемо: сообщение «На сайте» относится к **действительно доступному** файлу на Pages, а не к последнему коммиту в репозитории.
